[build] `--expandMacro` is silent by default AND macro-only (Nim 2.2.4)
  `nim c --expandMacro:myMacro file.nim` prints nothing unless the hint is
  enabled; the working invocation is:
    nim c --hint:ExpandMacro:on --expandMacro:myMacro file.nim
  which prints `Hint: expanded macro: 42 [ExpandMacro]` with a file:line
  position. Templates are NOT covered — `--expandMacro` on a template
  stays silent even with the hint on; for template semantics use a minimal
  runtime probe (`nim c -r`). Same silent-no-op family as `--expandArc`
  with a wrong target.

[footgun] `sqrt` needs `import std/math`; not auto-imported (Nim 2.2.4)
extends the "split needs std/strutils" entry (same mechanism). In a
unittest file importing only std/unittest, calling sqrt() fails:
  Error: undeclared identifier: 'sqrt'
  candidates (edit distance, scope distance): 'set', 'shr'
Fix: `import std/[unittest, math]`. min/max/clamp ARE in system; the
math-routine family (sqrt, ln, exp, pow, sin...) is not.

[idiom] `block` is a Nim keyword — illegal as a parameter name (Nim 2.2.4)
Trap: naming a proc parameter `block` (e.g. a JSON block) fails to compile.
Symptom: `Error: expected closing ')'` pointing at the parameter line —
misleadingly a *syntax* error, not a "keyword in use" error.
Fix: rename the parameter (e.g. `riderBlock`); keywords like `block`,
`type`, `addr`, `mixin` cannot be parameter names.
```nim
proc merge(b: JsonNode) = discard     # fine
proc merge(block: JsonNode) = discard # Error: expected closing ')'
```
