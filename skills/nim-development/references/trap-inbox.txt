[footgun] No `isFinite` for floats in `std/math` (Nim 2.2.4)
  Reaching for `x.isFinite` (habit from other languages) does not compile:
  `Error: undeclared field: 'isFinite' for type system.float64`.
  Gate on `classify` instead:
    func finite(x: float64): bool {.inline.} =
      classify(x) in {fcNormal, fcSubnormal, fcZero, fcNegZero}

[cli] `nim check` accepts only one file per invocation (Nim 2.2.4)
  Batch-style checking a project — `nim check --styleCheck:error src/a.nim
  src/b.nim` — fails with an error that misleads toward a `--run` problem:
  `Error: arguments can only be given if the '--run' option is selected`.
  The actual cause is the argument count. Check one file per invocation,
  or check an entry module that imports the rest of the project.

[parsecsv] `CsvParser.open` string overload raises CsvError on a missing file; the stream overload asserts on nil (Nim 2.2.4)
  Opening via `p.open(newFileStream(f, fmRead), f)` crashes when the file
  is missing, because `newFileStream` returns nil instead of raising:
  `Error: unhandled exception: lexbase.nim(141, 9) 'input != nil'`.
  Use the string overload instead — a missing file then raises
  `CsvError: Error: cannot open: <path>` (CsvError is `object of IOError`),
  so one `except IOError` handler covers it and the message names the path:
    var p: CsvParser
    p.open(path)          # missing file -> CsvError "cannot open: <path>"
    p.readHeaderRow()
    while p.readRow(): discard p.rowEntry("col")  # header-keyed access

[sequtils] `mapIt` takes an expression over `it`, not a lambda (Nim 2.2.4)
  Writing `toSeq(0..<n).mapIt(_ => 300.0)` (JS/Python muscle memory) fails
  at the call site with `Error: undeclared identifier: '=>'` — there is no
  `=>` operator. mapIt's parameter is already each element: use `it`
  directly (`mapIt(it * 2.0)`), or `newSeqWith(n, 300.0)` for constant
  fills.

[modules] Recursive imports fail only for some import orders (Nim 2.2.4)
  Two modules importing each other (a imports b for a type, b imports a
  for another type) compile cleanly when the entry file imports them in
  one order and fail in the other, with a misleading error pointing at a
  name:
    src/io.nim(115, 22) Error: undeclared identifier: 'PaceSegment'
    This might be caused by a recursive module dependency:
    src/integrator.nim imports src/io.nim
    src/io.nim imports src/integrator.nim
  The cycle is real, but it usually hides an *unused* import — integrator.nim
  imported io without referencing anything from it. Remove the unused
  import rather than restructuring; a cycle only survives unnoticed while
  some import order happens to resolve it, so CI must compile tests in
  every import order or the trap resurfaces later.

[idiom] triple-quoted string literals do NOT process escape sequences
  Triple-quoted literals ("""...""") keep backslash sequences as-is;
  only r"" differs from "" in escape handling, not """ from "". Symptom:
  a TOML/regex test literal written as """s = "a\tb"""" put two
  characters (\, t) on disk where one TAB was intended — the parser
  under test "wrongly" rejected or mis-parsed, and the test failure
  pointed at the code, not the literal. Verified on Nim 2.2.4 with
  echo repr("""a\\tb""") -> "a\\\\tb" (both backslashes retained).
  Fix: build such fixtures from an ordinary "..." literal where \t, \n,
  \\ are processed, or concatenate: "[rider]\n\ns = \"a\\tb\"\n".

[footgun] symbols declared inside `suite` are invisible to later suites
  unittest's `suite` is a template, so consts and helper procs declared
  inside it are scoped to that suite. Symptom: a helper defined in suite
  A and reused in suite B fails with "undeclared identifier" pointing at
  suite B's body, even though the definition is 40 lines above in the
  same file. Fix: hoist shared consts/procs to module level (outside the
  suite), or duplicate them per suite. (Observed Nim 2.2.4, std/unittest.)

  (Recurrence 2026-08-31, same trap, same file: a const declared inside
  suite "Rider schema strictness" reused by a later tuning_log suite —
  "undeclared identifier: 'riderScenarioTemplate'" with spell-suggest
  pointing at the top-level twin. Confirms the hoist-to-module-level fix.)

[footgun] `newSeqWith` lives in `std/sequtils`, not `system` (Nim 2.2.4)
  Extends the `[footgun] filterIt lives in std/sequtils` entry (same trap
  class, different symbol). A test file importing only `std/[unittest, os,
  math]` that calls `newSeqWith(120, 400.0)` fails with:
    Error: undeclared identifier: 'newSeqWith'
    candidates (edit distance, scope distance); see '--spellSuggest':
     (4, 7): 'newSeq'
  Fix: add `std/sequtils` to the import list. Generalization: seq
  constructors/builders (`newSeqWith`, `mapIt`, `filterIt`, `toSeq`) are
  all in sequtils — `system` auto-imports none of them.

[footgun] for-loop tuple unpacking vs tuple-typed arrays (Nim 2.2.4)
  Hit while iterating `for bad, key in [("cp_w = 0.0", "cp_w"), ...]` in a
  unittest. Compile error:
    Error: type mismatch
    Expression: key & " ="
      [1] key: (string, string)
  The two-variable unpacking did NOT happen — `key` was the whole tuple.
  (Nim's tuple-unpacking in `for` loops applies to the *iteration variable*
  when items() yields tuples; in this instance the literal's element type
  was inferred as an unnamed tuple and the two-name form silently bound a
  tuple to the second name.) Fix pattern that compiled first try:
    for pair in [...]:
      let bad = pair[0]; let key = pair[1]

[footgun] replace() has NO occurrence-count parameter
  `strutils.replace(s, sub, by)` is the only string overload; there is no
  `replace(s, sub, by, n)` (that's Python). Passing a 4th arg:
    Error: type mismatch ... func replace(s, sub: string; by = ""): string
    extra argument given
  Use a manual single-substring replace (find + substr) if you need
  first-occurrence-only semantics.

[footgun] proc call order DOES matter across a module (Nim 2.2.4)
  Contrary to the "procs are hoisted within a module" prior, calling
  `buildTuningLog` from a `writeSummaryPower` defined EARLIER in the same
  module failed:
    Error: undeclared identifier: 'buildTuningLog'
  with spell-suggest garbage. Same module, module-scope proc — still
  rejected. Reordering the callee above the caller fixed it. (Suspect:
  mutual-recursion carve-outs are narrower than assumed; don't rely on
  forward use at module scope without `forward`.)

[json] %* macro cannot take a heterogeneous if/else ternary
  `%*{"k": if cond: x else: newJNull()}` — "type mismatch: float and
  JsonNode". The macro evaluates the expression uniformly, so both branches
  must share a type. Precompute the node:
    let j = if cond: %(x) else: newJNull()
    %*{"k": j}

[unittest] `check`/`fail` inside a helper proc called from `test` flips
the exit code silently — all tests still print [OK]
Trap: std/unittest `check`/`fail`/`checkpoint` invoked in a plain proc
that a `test` block calls.
Symptom: binary exits 1 with every test listed as [OK]; the only trace is
a bare "Check failed: ..." line (easy to miss among [OK] lines). Observed
Nim 2.2.4 when a shared `expectError(text, needles)` helper ran `for n in
needles: check e.msg.contains(n)` — the failing needle failed no visible
test yet `nim c -r` reported "execution of an external program failed".
Fix: check the exit code, not just [OK] lines; put `checkpoint(needle)`
before each helper `check` so the bare line is attributable, and treat
any "Check failed:" output as a hard failure.

[footgun] `for k in t.keys` iterates a Table in hash order — the key
your error names is arbitrary
Trap: a validation/error-reporting loop over `Table[string, ...]` keys
that raises on the FIRST offending key.
Symptom: test asserts the message names key "cp_w" but the raised error
names "start_offset_m" — insertion order is NOT iteration order
(std/tables, unordered hashing; all Nim 2.x).
Fix: don't rely on iteration order for which error fires. Sort or
deliberately check known keys first:
    for k in toSeq(t.keys).sorted():  # deterministic offender
      if k notin allowed: raise ...
(or assert one key per test case, isolating the offender).

[footgun] indexing an optional table with `t[name]` raises a bare
KeyError instead of your schema error
Trap: `doc.tables["power"]` on a document where the block is optional
(or arrives via another spelling).
Symptom: "Unhandled exception: key not found: power [KeyError]" — the
clean SchemaError path never runs; exit code is the unhandled-exception
crash, not your documented code.
Fix: branch on membership before indexing:
    if name in doc.tables: ... doc.tables[name] ...
    # or: doc.tables.getOrDefault(name, TomlTable())

[build] `nim check` accepts exactly ONE file argument
Trap: `nim check --styleCheck:error a.nim b.nim c.nim`.
Symptom: "Error: arguments can only be given if the '--run' option is
selected" — looks like a flag conflict, is actually the multi-file arg.
Fix: loop one file per invocation:
    for f in src/*.nim tests/*.nim: nim check --styleCheck:error $f
